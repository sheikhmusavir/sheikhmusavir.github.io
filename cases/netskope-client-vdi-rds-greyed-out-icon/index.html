Case 11Client and steeringNetskope Client on VDI/RDS: greyed-out icon, working tunnel

The greyed-out icon on a working tunnel

The UI said security was off. Traffic said otherwise — and both were telling the truth.

~19concurrent sessions
0x800705afcommit limit reached
2symptoms, one cause

Symptom

On a pooled VDI/RDS session host, the client's Internet Security icon greyed out for all users — yet browsing was still steered and policy blocks still enforced, so protection was demonstrably working.

Investigation

Cross-referenced the UI process log against the service log and found host memory commit exhaustion, which had left the system management service unresponsive. That broke the client's ability to read BIOS serial and CPU ID, so it couldn't derive a stable hardware ID — and without it, decryption of the per-user encrypted credential store failed.

Root cause

The UI re-reads that encrypted store on every redraw, so it greyed out; the background service kept its cached tunnel state and carried on steering. One host-level resource problem, two very different symptoms. The registry fallback for hardware ID had been stripped from the VDI image, leaving no backup path.

Fix

Drain and reboot the host as the immediate fix, then commit/page-file sizing work with the platform team for ~19 concurrent sessions — plus a product request for a hardware-ID fallback where the management service is unavailable and the registry value is absent.
