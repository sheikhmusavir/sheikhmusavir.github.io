Case 01DLPAadhaar DLP regex false positives under RE2

The national-ID pattern with an 80% noise problem

A customer's Aadhaar regex matched nearly every 12-digit number in their traffic.

2structural rules exist
~80%of 12-digit strings matched
12digit target format

Symptom

An Aadhaar (India national ID) detection rule flooded the customer with false positives — order IDs, transaction references, and phone numbers all triggered it.

Investigation

Researched the issuing authority's actual numbering structure: only two rules exist — first digit 2–9, and a Verhoeff checksum as the 12th digit. The middle digits are random, so no regex refinement could ever be selective. The unformatted 12-digit branch matched roughly 80% of all 12-digit strings.

Root cause

Checksum validation needs arithmetic, which no regex can express — and the platform's RE2-style engine additionally rejects lookarounds ((?…) constructs), ruling out boundary tricks.

Fix

Word-boundary-hardened pattern within RE2 limits, layered with the platform's predefined identifier and proximity keywords. Delivered a categorized synthetic test corpus — match, non-match, and boundary cases — so the customer could verify before rollout.

Real investigation from enterprise Netskope support. Customers and vendors are anonymized.
