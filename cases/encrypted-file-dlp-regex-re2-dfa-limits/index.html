Case 02DLPDetecting cipher files with an RE2-safe DLP regex

The encrypted file that looked like phone numbers

Cipher text kept tripping phone-number detection — and every "fix" regex crashed the compiler.

7.89bits/byte entropy
{50}fixed quantifier
0hits on normal documents

Symptom

A near-random cipher file (7.89 bits/byte entropy) triggered the phone-number rule constantly. The customer wanted a pattern to identify cipher files so they could be excluded.

Investigation

Byte-distribution and entropy analysis, then systematic elimination: negated Unicode classes timed out at DFA compilation, high-byte patterns never matched because the engine strips non-ASCII before scanning, and bounded quantifiers like {150,1024} blew the compile budget — confirmed by a "Regex compilation timed out" error captured in a HAR file.

Root cause

RE2 compiles to a DFA with a strict size budget; large quantifier upper bounds multiply states until compilation fails. The idea was right — the state-machine cost was the problem.

Fix

A fixed-quantifier pattern — [!-~]{50} — matching 50+ consecutive printable non-space characters. Minimal DFA, instant compile, tens of thousands of hits on cipher files, zero on normal documents.

Real investigation from enterprise Netskope support. Customers and vendors are anonymized.
