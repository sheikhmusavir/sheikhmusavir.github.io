03 / Investigation method

Every clue has a place in the timeline.

I try to replace “it looks like the proxy” with a testable statement: which request, which decision, which hop, and which evidence proves where the behaviour changes.

PCAPHARClient logsDNS / EDNSTLSSAMLPolicy events
STEP / 01

Establish the baseline

Capture the exact symptom, scope, timing and reproduction steps. Compare the affected path with a known-good path before changing policy.

ReproduceScopeCompare
STEP / 02

Follow the evidence

Correlate packet captures, HAR entries, client logs, DNS answers, TLS handshakes and policy events. Find the first point where the expected flow changes.

WiresharkHAR analysisLogs
STEP / 03

Isolate the control boundary

Separate identity, client steering, inspection, application behaviour and destination response. Change one variable at a time and record what the result proves.

IdentitySteeringPolicy
STEP / 04

Validate the fix — then document it

Repeat the original test, check that the control still enforces the intended policy, and document the root cause, corrective action and remaining caveats.

RetestLeast privilegeRunbook
